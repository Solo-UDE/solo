# Solo Skills Marketplace — Design Spec

**Date:** 2026-04-18
**Status:** Approved (brainstorming complete)
**Author:** Sachin + Claude
**Target repo:** `solo/` inside `Orbit_Main`
**Separate repo to create:** `github.com/solo/skills-registry`

## 1. Goal

Turn Solo's placeholder `SkillsSection` in the vault sidebar into a full open-source skills marketplace. Skills are domain-agnostic (poetry, finance, photography, UI, mathematics, …) and work for any model running in a Solo agent session. Installed skills are always discoverable by the agent; uninstalled skills are semantically searched on every user turn and surfaced as install suggestions above the input box. Skills are markdown-only, use the `AGENTS.md` open standard, and are fully portable to Cursor / Codex / Windsurf.

## 2. Decisions locked in brainstorming

| # | Decision |
|---|---|
| 1 | Registry lives in a public GitHub repo `github.com/solo/skills-registry`, catalog is static JSON. |
| 2 | Monorepo-of-skills model: registry repo contains both `registry.json` and every skill's files under `skills/<name>/`. |
| 3 | Runtime: **hybrid**. Installed skills auto-injected into the system prompt. Marketplace search runs automatically on every user turn as a background UI concern (not a model tool) and surfaces suggestions above the input box with `[Download]` `[View skill]` `[Skip]`. |
| 4 | Trust model: **markdown only**. No executable scripts or binaries. Claude Code-compatible skill format. |
| 5 | File format: `AGENTS.md` is canonical per-skill; `SKILL.md` accepted as a fallback for Claude Code interop; a workspace-root `AGENTS.md` is auto-generated as an index of installed skills. |
| 6 | Default UI skill: bundled in the Tauri binary via `include_dir!`, extracted to `~/.solo/skills/ui/` on first launch, updated via the normal marketplace update path. |

## 3. System architecture

```
github.com/solo/solo                    ← the IDE (Tauri app)
github.com/solo/skills-registry         ← public monorepo of all skills (MIT, PR-based)
~/.solo/skills/                         ← per-user installed skills on disk
```

Inside the Tauri app:

```
VaultSidebar → SkillsSection ──┐                Settings → SkillsTab (existing, unchanged)
  ├─ Installed tab             │
  ├─ Marketplace tab           │
  ├─ Forks tab                 │
  └─ skill-preview panel       │
                               │
Agent chat → SuggestionBanner above input box
                               │
skillStore (Zustand + Immer)   │
  ├─ installed[]               │       reads ~/.solo/skills/
  ├─ registry                  │       cached registry.json
  ├─ suggestions[]             │       output of marketplace search
  └─ tweaking?                 │       UI state for agent-tweak flow
                               │
              (Tauri IPC)      │
                               ▼
skills_commands.rs
  ├─ skills_list_installed
  ├─ skills_fetch_registry
  ├─ skills_search_marketplace
  ├─ skills_install
  ├─ skills_uninstall
  ├─ skills_write_installed
  ├─ skills_write_workspace_agents_md
  └─ skills_extract_bundled

reqwest HTTP client (registry fetch + tarball download)

agent-bridge sidecar (Node.js)
  skills.ts — reads ~/.solo/skills/*/AGENTS.md, injects name+description into system prompt,
              exposes load_skill(name) tool
```

### Primary user journeys

**Journey A — Installed skill in use:**
```
user message → agent-bridge reads ~/.solo/skills/*/AGENTS.md → formats frontmatter + body
into system prompt → model responds using skill.
```

**Journey B — Uninstalled-skill suggestion:**
```
user message → skills_search_marketplace(message) → semantic search over cached registry
embeddings → top hit above threshold + not already installed → BackendEvent::SkillsSuggestion
→ banner renders above input → user clicks Download → skills_install(id) fetches tarball
from solo/skills-registry → writes to ~/.solo/skills/<id>/ → workspace AGENTS.md
regenerated → next turn picks up new skill automatically.
```

```json
      "license": "MIT",

      "created_at": "2026-04-18",
      "updated_at": "2026-04-18"
    }
  ]
}
```

### Per-skill `AGENTS.md`

```markdown
---
name: ui
version: 1.0.0
description: Build and refine user interfaces with Tailwind CSS...
categories: [design, frontend]
author: solo-team
license: MIT
tags: [tailwind, ui, css]
---

# ui

This skill helps you build user interfaces with Tailwind CSS...
```

Required frontmatter: `name`, `description`. All other fields optional.

### Protocol types (`crates/solo-protocol/src/lib.rs`, ts-rs derive)

```rust
#[derive(TS, Serialize, Deserialize, Clone, Debug)]
#[ts(export)]
pub struct RegistryEntry {
    pub id: String,
    pub name: String,
    pub version: String,
    pub description: String,
    pub categories: Vec<String>,
    pub author: String,
    pub license: String,
    pub tarball_url: String,
    pub sha256: String,
    pub tags: Vec<String>,
    pub updated_at: String,
}

#[derive(TS, Serialize, Deserialize, Clone, Debug)]
#[ts(export)]
pub struct SkillSuggestion {
    pub entry: RegistryEntry,
    pub score: f32,
    pub reason: String,
}

#[derive(TS, Serialize, Deserialize, Clone, Debug)]
#[serde(tag = "type")]
pub enum BackendEvent {
    // existing variants...
    #[serde(rename = "skills:suggestion")]
    SkillsSuggestion { session_id: String, suggestions: Vec<SkillSuggestion> },
    #[serde(rename = "skills:installed")]
    SkillsInstalled { skill_id: String },
    #[serde(rename = "skills:registry_updated")]
    SkillsRegistryUpdated,
}
```

Run `bun run gen:bindings` from `solo/` after editing.

### On-disk installed layout

```
~/.solo/skills/
├── ui/
│   ├── AGENTS.md              canonical
│   ├── ui-picker.md
│   ├── finalize.md
│   ├── design-guidelines/
│   └── .solo-origin.json      {source, id, version, installed_at, modified}
└── my-custom-skill/
    └── AGENTS.md              no .solo-origin.json → user-authored
```

`.solo-origin.json` is the fork-tracking mechanism.

### Workspace-root `AGENTS.md` (auto-generated)

```markdown
<!-- solo:begin -->
# Installed Solo Skills
- **ui** — Build and refine UIs with Tailwind CSS.
- **poetry-writer** — Generate and critique poetry in various forms.

Full instructions at `~/.solo/skills/<name>/AGENTS.md`.
<!-- solo:end -->
```

If the root file already exists, Solo replaces only the `<!-- solo:begin -->...<!-- solo:end -->` block. If it doesn't exist, Solo creates the file with just that block.

## 5. Runtime agent integration

### Installed skills (always loaded)

`agent-bridge/src/skills.ts` already injects skills via `formatSkillsForPrompt()`. Two updates:

1. Accept both `AGENTS.md` and `SKILL.md` (AGENTS.md wins if both present).
2. Inject only `name + description` into the system prompt. Full body is loaded on demand via a `load_skill(name)` tool exposed to the model. Token cost becomes O(installed_count), not O(total_body_size).

Generated block:
```
## Available Skills (installed)
The user has these skills available. Call `load_skill(name)` to read the full instructions
for any skill that matches the current task.

- **ui**: Build and refine UIs with Tailwind CSS...
- **poetry-writer**: Generate and critique poetry...
```

### Marketplace search (automatic, per-turn)

On every user message, the frontend dispatches `skills_search_marketplace(query=message, k=5, threshold=0.72)`:

1. Rust command computes query embedding via `solo-embeddings`.
2. Compares cosine similarity against pre-computed embeddings for every `registry.json` entry (cached on first registry fetch, re-computed when `version` changes).
3. Filter: above threshold AND not already installed AND not dismissed this session.
4. Emit `BackendEvent::SkillsSuggestion` with top 3 results.
5. Frontend updates `skillStore.suggestions`; banner renders above input.

The model is **not** involved in this loop. The banner is UI, not prompt.

### Confidence and UX tuning

- Default cosine threshold: `0.72`, user-adjustable in Settings → SkillsTab.
- Max 3 suggestions per turn.
- Session-scoped dedupe: once a user dismisses a skill, it's not re-suggested this session.
- Persistent dedupe: after 3 dismissals across sessions, never suggest again (stored in `~/.solo/settings.json`).

### Agent-driven tweak flow

"Tweak with agent" opens a fresh agent panel with:
- Preloaded context: the full `AGENTS.md` body
- System message: `The user wants to personalize this skill for their use case. Ask what they want to change, then propose markdown edits.`

Agent converses, proposes edits; on approval, `skills_write_installed(id, content)` writes the file and flips `.solo-origin.json.modified = true`. Next turn uses the updated skill.

## 6. UI / UX

### VaultSidebar → SkillsSection

Replace placeholder at `apps/desktop/src/components/sidebar/vault/SkillsSection.tsx`.

Three tabs:
- **Installed** — everything in `~/.solo/skills/`. Row actions: View · Tweak with agent · Uninstall · Check for update.
- **Marketplace** — categories (Design, Writing, Finance, Science, Life, Code, …) + text search. Row actions: Install · View · author tag.
- **Forks** — installed skills where `.solo-origin.json.modified = true`. Shows upstream version vs. local state.

### Suggestion banner

Rendered above `ChatInput` when `skillStore.suggestions.length > 0`:

```
💡 This task might benefit from the `poetry-writer` skill from the marketplace.
   [ Download ]  [ View skill ]  [ Skip ]
```

- Download → `skills_install(id)`; toast "Installed. Used on your next message."; then optional "Tweak with agent?" link.
- View skill → opens `skill-preview` panel (read-only, no install).
- Skip → dismiss for this session (persistent after 3 dismissals).

### Settings → SkillsTab

Unchanged except for one new row: **"Skills Marketplace"** linking to the vault SkillsSection. The settings tab remains the place for source adapters (Claude Code dirs, Codex dirs).

### First-launch flow

1. `skills_extract_bundled` copies the embedded `ui` skill to `~/.solo/skills/ui/`.
2. Writes `.solo-origin.json` with `{source: "bundled", version, installed_at, modified: false}`.
3. One-time toast: "The UI skill is ready. Try `/ui` in the agent panel."

### Update flow

On app launch and every 24h:
1. Fetch `registry.json` (cached in `~/.solo/cache/registry.json`).
2. Compare versions for each installed-from-registry skill.
3. Unmodified + newer upstream → "Update available" prompt in Installed tab.
4. Modified + newer upstream → "Upstream updated — yours is forked. View diff / Discard fork / Keep fork".

## 7. Security and safety

- **No executable skill content.** Markdown + assets only. CI in `solo/skills-registry` rejects any `.sh`, `.py`, `.js`, `.ts`, `.exe`, ELF, Mach-O, PE.
- **SHA-256 verification** on tarball download. Mismatch aborts install.
- **Path traversal prevention.** Tarball entries normalized and constrained to `~/.solo/skills/<id>/`; entries escaping the dir are rejected.
- **Size limit.** 5 MB per skill tarball, enforced both CI-side and client-side.
- **Registry URL override.** `settings.skills.registry_url` defaults to the official repo; users can point at a fork for private/enterprise use.
- **Prompt injection mitigation.** Skill bodies are loaded as markdown content (not as system instructions). Frontmatter is validated against a schema before injection. A malicious skill can try to confuse the model, but cannot execute code or exfiltrate data.

## 9. Open-source posture

- `solo/skills-registry`: MIT, public, PR-based contributions.
- `CONTRIBUTING.md` documents authoring, required fields, banned content, review criteria.
- `CODEOWNERS` routes category folders to domain reviewers.
- Users/orgs can fork the registry and point Solo at the fork via `settings.skills.registry_url`.

## 10. Phased rollout (shapes the implementation plan)

**Phase 1 — Foundation.** AGENTS.md/SKILL.md dual parsing. Protocol types and ts-rs bindings. `.solo-origin.json` tracking. `include_dir!`-based UI-skill bundling + first-launch extraction. Workspace-root `AGENTS.md` generator.

**Phase 2 — SkillsSection UI.** Replace placeholder with Installed / Marketplace / Forks tabs. Installed tab reads from `skillStore`. Marketplace tab reads cached `registry.json`. `skill-preview` panel for View.

**Phase 3 — Registry fetch + install pipeline.** `skills_fetch_registry` with 24h caching. `skills_install` (tarball + sha256 + path-traversal checks). `skills_uninstall`. Update detection.

**Phase 4 — Semantic search + suggestion banner.** Pre-compute embeddings for all registry entries on first fetch. `skills_search_marketplace`. Per-turn suggestion emission. Banner above ChatInput.

**Phase 5 — Agent tweak flow.** "Tweak with agent" wiring. Preloaded context. Modification persistence.

**Phase 6 — Testing + hardening.** Rust test modules, Vitest suite, Tauri E2E happy path, registry CI workflow.

Each phase ends with green tests and a manual smoke pass. Phases 1–2 ship a usable system; 3–4 add discovery; 5 adds personalization; 6 hardens.

## 11. Out of scope for v1

- Executable skills / script-based skills (revisit only if a concrete use case demands it).
- Ratings, reviews, author accounts (marketplace is PR-curated for v1).
- Paid skills / monetization.
- Skill dependencies (one skill requires another).
- Auto-activation of skills based on file patterns (model decides via `load_skill`).
- Private team registries beyond the simple "change URL" primitive.
