Skill pill UX — pick the behavior you want

The issue: after sending a message with a skill attached, the pill stays in the input and the sent message shows no trace that a skill was active. Here are four distinct ways to fix it. Each card is interactive — type something, click Send, and watch what happens.

Option A Clear on send

The pill is a one-time attachment. On send, it animates into the user message as a badge; the input returns to a clean state. Re-attach explicitly for the next message.

per-file-commit

Pros

  • Unambiguous — every message declares its skills
  • Zero stale-state risk
  • Clean input after send

Cons

  • Re-attach each message when iterating

Option B Sticky + trace

The pill persists for the session (current behavior). Every sent message gets a small "used:" badge so the history is unambiguous. Detach with × when done.

per-file-commit

Pros

  • Low friction for repeated use of one skill
  • Message history still shows what applied

Cons

  • Easy to forget a skill is still attached

Option C Pin to keep

Default = clear on send. A pin icon on each pill flips it to sticky. Unpinned pills have a dashed ghost border; pinned pills are solid. Best of both modes under explicit user control.

per-file-commit 📌

Pros

  • Explicit intent, no surprises
  • One-off and batch flows both first-class

Cons

  • Extra affordance to learn (the pin icon)

Option D Inline chip

The skill lives inside the editor as a non-editable chip at the start of the message — like a mention. It sends with the text, then disappears when the input clears. Visually inseparable from the content.

/per-file-commit

Pros

  • Skill is literally part of the message — zero ambiguity
  • Feels familiar (like @mentions / #channels)

Cons

  • Implementation cost in Lexical (custom node)
  • Takes up inline space in the editor
